**Flow:** F10 Export & share
**Static verdict from audit:** GAP (static code read; `[RUNTIME]` items need a device)
**Build / env:** main @ `0dba134` · iOS 17+ · Simulator/Device · StoreKit env: Xcode config (`Products.storekit`) · n/a Apple ID

### Expected
User-facing wording only; the app never writes to the clipboard without a user action that says so.

### Actual
Export sheet has a "Session recording" section with footer "Debug export: the mic audio as the model heard it…" and a "Note events" row that copies JSON to the clipboard ("paste it into chat"). The listening screen has an always-available toolbar Export that also writes the clipboard ("paste it here"). This replaces whatever the user had copied.

### Location
`Sources/App/ExportView.swift:39-54,163-184`; `Sources/App/ListeningView.swift:304-312,418-440`; `Sources/App/SessionDebugExport.swift`.
Root cause: Dev tooling left in the production UI.

### Repro
Copy some text > record a take > Export > Note events > clipboard is replaced.

Repro rate: always

### Severity
P3 — Clipboard overwrite plus developer copy visible in a store build; privacy-adjacent.

### Suggested fix
Remove all `UIPasteboard` writes and developer copy; keep sharing as plain files labelled "Share recording (WAV)" / "Share notes (JSON)"; drop the listening-screen toolbar Export. No feature flags.
