**Step ID:** F9.4
**Flow:** F9 Import audio / MIDI / video
**Static verdict from audit:** GAP (static code read; `[RUNTIME]` items need a device)
**Build / env:** main @ `0dba134` · iOS 17+ · Simulator/Device · StoreKit env: Xcode config (`Products.storekit`) · n/a Apple ID

### Expected
Every way of creating a take (mic, audio, MIDI, video) respects `ProStore.freeSaveLimit`: a free user with 3 saved pieces gets the held-take/paywall path on the 4th.

### Actual
`importAudio` calls `library.addTake` directly, so an audio import always saves and opens the take. MIDI (`importMIDI`) and video (`importVideo`) go through `saveImportedScore` and are gated.

### Location
`Sources/App/LibraryView.swift:297-301` (ungated `open(library.addTake(score:events:))`); gated reference path `LibraryView.swift:207-221`, used at :240 and :269.
Root cause: Gate lives in the view helper `saveImportedScore`, not in `TakeLibrary.addTake`; the audio branch was never routed through it.

### Repro
1. Fresh install, not Pro. 2. Record/import until 3 takes exist. 3. Library > import menu > Choose Audio > pick a 10 s .m4a with notes. 4. A 4th take is saved and opened; no banner, no paywall.

Repro rate: always

### Severity
P1 — Direct revenue leak on the primary free-to-paid gate.

### Suggested fix
Replace the `open(library.addTake(...))` in `importAudio` with `saveImportedScore(score, events: notes)`. Better: enforce the limit in one place (`TakeLibrary.addTake` returning a result / a `SaveGate` helper used by all four paths).
