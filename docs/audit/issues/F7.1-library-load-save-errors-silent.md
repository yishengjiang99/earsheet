**Step ID:** F7.1
**Flow:** F7 Library persistence & storage
**Static verdict from audit:** GAP (static code read; `[RUNTIME]` items need a device)
**Build / env:** main @ `0dba134` · iOS 17+ · Simulator/Device · StoreKit env: Xcode config (`Products.storekit`) · n/a Apple ID

### Expected
A decode/read failure preserves the file, tells the user, and keeps readable takes; write failures (disk full) are reported.

### Actual
`load()` uses `try?` for read and decode and returns with empty `takes`; the next `addTake`/`delete`/`setTempo` calls `save()` which atomically replaces the file with only the new data. One undecodable element (e.g. after a model change) loses all takes. `save()` also swallows encode/write errors.

### Location
`Sources/App/TakeLibrary.swift:248-254` (load) and `:256-260` (save).
Root cause: No error handling or backup on persistence I/O.

### Repro
Corrupt `Application Support/<bundle id>/takes.json` (truncate last bytes) > launch (empty Library) > record a take > relaunch: only the new take exists.

Repro rate: always (file-system level)

### Severity
P2 — Permanent loss of all saved pieces (Pro users' main asset) from a single bad byte or schema change.

### Suggested fix
On failure: move the file to `takes.corrupt-<timestamp>.json`, post a notice; decode elements individually (`[Failable<Take>]`) to keep valid ones; surface write errors via `postNotice`. Inject the URL for tests.
