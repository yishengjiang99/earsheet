**Step ID:** P1.8
**Flow:** P1 Free-tier limits & paywall triggers
**Static verdict from audit:** GAP (static code read; `[RUNTIME]` items need a device)
**Build / env:** main @ `0dba134` · iOS 17+ · Simulator/Device · StoreKit env: Xcode config (`Products.storekit`) · n/a Apple ID

### Expected
Per design, taps on locked items/user-initiated entries never count; only automatic presentations start the 72 h cooldown and the 5-dismissal lifetime cutoff.

### Actual
`ListeningView` calls `triggers.recordDismiss()` whenever the held-take paywall closes without Pro, but that sheet is opened only by user taps (banner button, dialog "Keep this one with Pro"). Five such dismissals disable all future automatic prompts and each starts a 72 h cooldown.

### Location
`Sources/App/ListeningView.swift:119,332-336,452`; caps `Sources/App/PaywallTriggers.swift:34-52,65-68`.
Root cause: Dismiss accounting is attached to the sheet, not to how it was presented.

### Repro
Held take > tap Keep it > close paywall x5 (across sessions): `paywall.dismissCount == 5` and `canShowAuto` is false forever.

Repro rate: always

### Severity
P3 — Over-suppresses legitimate upsells; contradicts PAYWALL_FLOW §2.

### Suggested fix
Record dismissals only for presentations that went through `canShowAuto/recordAutoShown` (LibraryView save-limit path); remove the `recordDismiss` call in ListeningView.
