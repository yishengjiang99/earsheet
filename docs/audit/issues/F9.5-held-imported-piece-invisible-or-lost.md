**Static verdict from audit:** GAP (static code read; `[RUNTIME]` items need a device)
**Build / env:** main @ `0dba134` · iOS 17+ · Simulator/Device · StoreKit env: Xcode config (`Products.storekit`) · n/a Apple ID

### Expected
Imports at the limit behave like mic takes: the piece is shown in place with a "Not saved yet" banner and Keep it / Discard.

### Actual
`pendingScore` is hidden state. If the paywall is shown and dismissed nothing remains on screen; if caps suppress the paywall the alert says "Upgrade to Pro in Settings to keep this one — it's held for now." but there is nowhere to see it. A second import overwrites `pendingScore`; relaunch loses it; if the user later gets Pro (e.g. Restore in Settings), `onChange(of: isPro)` suddenly opens the stale piece.

### Location
`Sources/App/LibraryView.swift:20` (state), `:207-215` (hold), `:163-173` (resume).
Root cause: Held imports reuse none of the held-take UI built for the mic path.

### Repro
Free, 3 takes > import MIDI > dismiss paywall > Library shows nothing; import another file: first piece is gone.

Repro rate: always

### Severity
P2 — Silent loss of imported work at the monetization moment.

### Suggested fix
Open the held piece in the take screen with the existing `HeldTakeBanner` (via `TakeLibrary.looseTakes`/pending `Take`) and the same confirm-before-discard rules as [F5.6]; keep at most one held piece with a clear replace warning.
