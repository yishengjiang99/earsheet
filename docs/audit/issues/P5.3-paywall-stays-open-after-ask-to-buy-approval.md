**Flow:** P5 Pending / Ask to Buy
**Static verdict from audit:** GAP (static code read; `[RUNTIME]` items need a device)
**Build / env:** main @ `0dba134` · iOS 17+ · Simulator/Device · StoreKit env: Xcode config (`Products.storekit`) · n/a Apple ID

### Expected
When approval arrives (Transaction.updates -> Pro) the paywall closes and the user sees Pro state (matrix S8).

### Actual
`PaywallView` dismisses only from `buySelected()` when `purchase()` returns true. A pending purchase returns false with an alert; later approval flips `store.isPro` but nothing in the view observes it, so the paywall (with a live CTA) stays up.

### Location
`Sources/App/PaywallView.swift:227-237` (only dismissal on purchase); no `onChange(of: store.isPro)`; pending handling `Sources/App/ProStore.swift:126-129`.
Root cause: View-level dismissal is tied to the `purchase()` return value instead of entitlement state.

### Repro
Xcode StoreKit: enable Ask to Buy > buy yearly ("Purchase is pending approval.") > Manage Transactions > Approve. Paywall remains open, CTA still enabled.

Repro rate: always

### Severity
P2 — Confusing, and risks a double purchase; has a workaround (close).

### Suggested fix
Add `.onChange(of: store.isPro) { _, pro in if pro { dismiss() } }` to `PaywallView` (also covers restore completing elsewhere). Optionally use a neutral (non-error) pending presentation.
