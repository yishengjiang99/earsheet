**Build / env:** main @ `0dba134` · iOS 17+ · Simulator/Device · StoreKit env: Xcode config (`Products.storekit`) · n/a Apple ID

### Expected
A recording held by the free save limit is never lost without an explicit choice: leaving asks "Discard / Keep with Pro / Cancel".

### Actual
The held take screen's "Library" back button just calls `dismiss()`. The take (up to 60 s of the user's performance) is dropped with no confirmation; only the "Record again" path shows a dialog. The take's session WAV is also left on disk.

### Location
`Sources/App/ListeningView.swift:296-302` (back -> `dismiss()`); dialog only for re-record `:443-460`; WAV removal only in `restart()` `:215-218`.
Root cause: Held state has no discard transition besides `restart()`.

### Repro
Free account with 3 takes > record a 4th > Stop > Library (top-left) > cover closes; the take is gone, no prompt.

Repro rate: always

### Severity
P1 — Data loss of user-created content on a core path at the exact moment we ask for money.

### Suggested fix
Route the back button through a confirmation dialog ("This take isn't saved": Keep it with Pro / Discard / Cancel). Add `ListeningSession.discardPending()` that deletes the WAV.
