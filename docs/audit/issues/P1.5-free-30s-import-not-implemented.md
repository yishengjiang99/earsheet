### Expected
Paywall table ("Import length: First 30 s | Full length"), benefit row ("Full-length audio & video imports"), header copy, `docs/asc/review_notes.txt` and `docs/paywall/PAYWALL_FLOW.md` §1-2 describe real behavior: free imports transcribe the first 30 s; Pro transcribes the full allowed length.

### Actual
`ProStore.freeImportSeconds` is never read. `importAudio`/`importVideo` transcribe the whole file for free if it is <= 60 s (`AudioRecorder.maxSamples`) and throw `ImportError.durationLimitExceeded` for anything longer, for Pro too. So "full-length" is false (hard cap 60 s) and the free 30 s limit is absent. Selling Pro on a feature that does not exist is a Guideline 2.3.1/3.1.2 risk.

### Location
`Sources/App/ProStore.swift:31` (unused constant); `Sources/App/LibraryView.swift:284-301,252-270`; `Packages/HearSheet/Sources/HearSheet/AudioCapture.swift:229-240` (`maxSamples` pre-check throws); copy at `Sources/App/PaywallView.swift:110,244,255`; `docs/asc/review_notes.txt:16`.
Root cause: Documented design (free path "trims to 30 s before transcription", PAYWALL_FLOW §8) was never wired; copy shipped anyway.

### Repro
1. Free account. 2. Import a 50 s audio file. 3. Whole 50 s is transcribed and saved. 4. Import a 90 s file as Pro or free: "Could not read that audio file."

Repro rate: always

### Severity
P1 — Revenue/compliance: paywall and review notes advertise a gate and a Pro benefit that do not exist.

### Suggested fix
Default decision (product owner may overrule): implement the documented design. Free: `AudioImport.loadMono22050(url:maxSamples:)` already takes `maxSamples`; pass `Int(freeImportSeconds*22050)` for non-Pro and transcribe only that part. Pro: keep the 60 s engine cap and change copy to "up to 60 s" in PaywallView (header, benefit row, comparison row) and review_notes. Edit PaywallView copy lines only after Stream A has merged (same file). No flag. Prompt UI is ENH [P1.11].
