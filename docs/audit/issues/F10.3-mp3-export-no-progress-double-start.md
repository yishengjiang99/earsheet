### Expected
A visible "Rendering…" state and a disabled row while the MP3 renders; one share sheet per request.

### Actual
`exportMP3()` sets `isPreparing = true` but no view reads it. Rendering (44.1 kHz stereo SF2 render + LAME, up to 60 s of music plus 2 s tail) runs with no indicator; each extra tap starts another render and later another share sheet.

### Location
`Sources/App/ExportView.swift:18,141-152` (state set, never used in `body` :21-96).
Root cause: State variable added without UI binding or re-entrancy guard.

### Repro
Export a 60 s take > MP3 > no spinner; tap MP3 three times quickly.

Repro rate: always

### Severity
P2 — Looks broken for a few seconds; duplicate work.

### Suggested fix
Overlay `ProgressView("Rendering MP3…")`, `.disabled(isPreparing)` on rows, early return if already preparing.
