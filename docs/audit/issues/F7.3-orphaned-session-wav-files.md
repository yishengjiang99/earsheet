**Step ID:** F7.3
**Flow:** F7 Library persistence & storage
**Static verdict from audit:** GAP (static code read; `[RUNTIME]` items need a device)
**Build / env:** main @ `0dba134` · iOS 17+ · Simulator/Device · StoreKit env: Xcode config (`Products.storekit`) · n/a Apple ID

### Expected
A WAV exists only for takes that exist; failures/discards leave nothing in Application Support (which is also backed up).

### Actual
`stop()` calls `SessionDebugExport.persistSessionAudio(samples)` before transcription finishes. The failure paths (`Could not write the page`, `No notes found`) and a discarded held take never delete it; nothing sweeps unreferenced files at launch.

### Location
`Sources/App/ListeningView.swift:135` (write), `:155-160`, `:167-168` (no cleanup), `:296-302` (held discard); only `restart()` cleans `:215-218`; `Sources/App/SessionDebugExport.swift:41-50`.
Root cause: Persist-then-decide ordering plus no cleanup on error branches.

### Repro
Record 30 s of noise-with-notes that yields `No notes found`, repeat 5x; Application Support/<bundle id> accumulates `<uuid>.wav` files not referenced by `takes.json`.

Repro rate: always (file-system check)

### Severity
P2 — Unbounded storage growth, user recordings kept without a take (privacy page says recordings stay until the user deletes the take).

### Suggested fix
Persist the WAV only when a take (saved or held) is created; delete on failure/discard/cancel; add a launch sweep in `TakeLibrary.init` removing `*.wav` not referenced by any take.
