### Expected
Defined behavior: stop and save what was heard (or clearly pause), and show it on return; a call/Siri interruption shows a "Paused" indicator instead of a frozen timer.

### Actual
There is no `scenePhase` handling in the session or app, and `UIBackgroundModes` is absent. `AudioRecorder` only reacts to interruption *end*/route/config changes and silently restarts the engine; the elapsed timer is derived from captured samples so gaps are not represented. What the user sees after lock/unlock is unspecified (stale `.listening` screen, frozen timer).

### Location
`Sources/App/ListeningView.swift:57-94,243-258` (no lifecycle), `Sources/App/EarSheetApp.swift:13-19` (scenePhase only for ServerSync), `Packages/HearSheet/Sources/HearSheet/AudioCapture.swift:140-176` (`.began` ignored).
Root cause: Lifecycle/interruption states are not modeled in `ListeningSession.Phase`.

### Repro
Start listening > play 10 s > lock the phone 10 s > unlock. Observe timer/take state. Same with an incoming call. [RUNTIME, device only]

Repro rate: needs device

### Severity
P2 — Likely data loss or confusing state in the core recording flow; exact symptom needs a device.

### Suggested fix
Default: on `scenePhase == .background` during `.listening` call `stop()` (finalize and save/hold the take) and show a notice on return; add a `.paused` phase (or banner) on interruption began/ended. No background mode needed.
