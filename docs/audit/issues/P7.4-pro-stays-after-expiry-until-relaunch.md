**Flow:** P7 Entitlement checks
**Static verdict from audit:** GAP (static code read; `[RUNTIME]` items need a device)
**Build / env:** main @ `0dba134` · iOS 17+ · Simulator/Device · StoreKit env: Xcode config (`Products.storekit`) · n/a Apple ID

### Expected
After expiry the next foreground (and the next gated action) recomputes Pro from `Transaction.currentEntitlements`; gates apply without relaunch (matrix S12).

### Actual
`refreshEntitlement()` runs once in `ContentView.task` at launch, after purchase/restore, and on `Transaction.updates`. StoreKit emits no update at expiry, and nothing refreshes on `scenePhase == .active` or before the save/export gates, so a lapsed user keeps Pro for the whole process lifetime (and the cached `pro.isPro` keeps seeding `true` offline until the next launch refresh).

### Location
`Sources/App/ContentView.swift:20-23`; `Sources/App/ProStore.swift:45-50,165-180,193-204`; `Sources/App/EarSheetApp.swift:13-19` (scenePhase only feeds ServerSync).
Root cause: Entitlement refresh is event-driven only; no lifecycle or pre-gate refresh.

### Repro
Xcode StoreKit config attached: buy monthly > Debug > StoreKit > Manage Transactions > Expire > background and foreground the app > 4th save/MIDI export still allowed.

Repro rate: always

### Severity
P1 — Revenue: expired subscribers keep every Pro feature until relaunch.

### Suggested fix
Call `await proStore.refreshEntitlement()` on `scenePhase == .active` (EarSheetApp/ContentView) and at the top of each gate decision (`saveImportedScore`, `ListeningSession` limit check, `ExportView.exportMIDI/MusicXML`). Keep `Transaction.currentEntitlements` as the source of truth.
