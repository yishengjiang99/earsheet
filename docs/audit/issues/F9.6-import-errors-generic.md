### Expected
Specific, actionable text: too long ("up to 60 seconds"), no audio track in the video, unsupported/unreadable file.

### Actual
Every thrown error maps to "Could not read that audio file." or "Could not read that video's audio."; `ImportError.durationLimitExceeded`, `.noAudioTrack`, `.conversionFailed` and `TranscribeError.durationLimitExceeded` are swallowed.

### Location
`Sources/App/LibraryView.swift:271-276` and `:302-306`; error cases `Packages/HearSheet/Sources/HearSheet/AudioCapture.swift:307-311`, pre-check :236-239; `Transcriber.swift:109`.
Root cause: Single catch-all in both import tasks.

### Repro
1. Import a 90 s .m4a. 2. Alert: "Could not read that audio file." The user cannot tell that length is the problem.

Repro rate: always

### Severity
P2 — Confusing failure with a workaround (trim the file).

### Suggested fix
Switch on `AudioImport.ImportError` / `TranscribeError` and show: too long -> "That file is longer than 60 seconds. Trim it and try again."; noAudioTrack -> "That video has no audio."; else the generic text. Put the mapping in a small pure function.
